# host_audit

Роль только **проверяет** Linux-хост и пишет отчёт. Она не правит `sshd_config`, не ставит пакеты и не меняет firewall. Единственная запись — файлы отчёта на машине, с которой запущен Ansible.

Проверки закрывают базовый контур: SSH, ключи, sudo, ядро и права, парольную политику локальных учёток, обновления безопасности, firewall, лишние сервисы, auditd, доставку логов и время. Это не официальный отчёт CIS и не замена сертификации. Набор сознательно узкий и эквивалентен по смыслу CIS Level 1.

Подробности по каждому контролю: [docs/controls.md](docs/controls.md).

## Что проверяется

| ID | Ожидание |
| --- | --- |
| SSH-01 | В конфигурации, которую загрузит `sshd`, `PasswordAuthentication no`, включая `sshd_config.d` и `Match` |
| SSH-02 | `PermitRootLogin no`. `prohibit-password` не подходит |
| SSH-03 | Приватные ключи на машине, откуда запущен Ansible, закрыты парольной фразой |
| SSH-04 | В `/home` и `/root` целевого хоста нет приватных ключей в открытом виде |
| SSH-05 | В эффективной конфигурации есть `AllowUsers` или `AllowGroups` |
| SSH-06 | Работает fail2ban (jail `sshd`), sshguard или crowdsec с bouncer |
| SSH-07 | На управляющем контуре SSH требует ключ и второй фактор |
| SUD-01 | Нет `NOPASSWD: ALL` и нет выдачи всех команд кому-либо, кроме root |
| HRN-01 | Параметры ядра из `host_audit_sysctl` |
| HRN-02 | Права на `passwd`, `shadow`, `sshd_config`, drop-in и cron |
| HRN-03 | Политика паролей локальных учёток: `login.defs`, pwquality, история, faillock |
| UPD-01 | `unattended-upgrades` или `dnf-automatic` ставят security-обновления |
| FW-01 | Firewall с default-deny, открыты только порты из allowlist |
| SVC-01 | Нет запрещённых пакетов и сервисов, демо-учётки заблокированы, UID 0 только у root |
| AUD-01 | auditd включён и следит за identity, sudoers и сменой времени |
| LOG-01 | Логи уходят на центральный приёмник |
| TIM-01 | Служба времени запущена, серверы заданы, часы синхронизированы |

Статусы в отчёте: `pass`, `fail`, `warn`, `skip`. Поле `severity` — насколько плохо нарушение: `low`, `medium`, `high`, `critical`.

## Быстрый старт

Роль лежит в корне репозитория. Каталог называется `sorrowless.host_audit`, а Ansible не принимает такое имя из-за точки, поэтому для запуска её нужно видеть как `host_audit`.

```bash
./run-host-audit.yml -i inventory.example.yml
./run-host-audit.yml -i inventory/hosts.py -l web-01,web-02
```

Плейбук идёт с `become: true`: роль читает `/etc/shadow`, sudoers и вызывает `sshd -T`. `hosts: all` проверяет каждый хост инвентаря; список сужается флагом `-l`.

Отчёты складываются локально, по одному на хост. Имя в файле — каталог этого хоста в `host_vars`. Для `host_vars/web-01/` это:

- `/tmp/ansible/host-audit/web-01-host-audit.txt`
- `/tmp/ansible/host-audit/web-01-host-audit.json`

В обычном inventory имя каталога совпадает с именем хоста. Каталог отчётов создаётся с режимом `0700`, файлы — с `0600`. На целевых хостах роль ничего не записывает.

По умолчанию `host_audit_fail_on: high`. Если есть нарушение уровня high или critical, плейбук завершается ошибкой уже после записи отчётов. Чтобы только собрать отчёты:

```yaml
host_audit_fail_on: none
```

Бастион и другие хосты, где администратор входит интерактивно, отметьте отдельно. Без этого MFA не требуется и контроль SSH-07 получает статус `skip`.

```yaml
# inventory.example.yml
management:
  vars:
    host_audit_management_host: true
  hosts:
    bastion:
      ansible_host: 10.0.0.5
```

Каталоги ключей управляющей машины по умолчанию — `~/.ssh` пользователя, который запускает Ansible. Роль читает только заголовок ключа и не подбирает парольную фразу. Свой путь задаётся так:

```yaml
host_audit_controller_key_dirs:
  - /Users/admin/.ssh
```

Полный список порогов, портов, sysctl, пакетов и демо-учёток — в `defaults/main.yml`.

## Как читается sshd

OpenSSH берёт **первое** полученное значение параметра. Более поздняя строка его не перебивает.

На Debian и Ubuntu директива `Include /etc/ssh/sshd_config.d/*.conf` стоит в начале основного файла. Файлы каталога читаются по алфавиту раньше остальных строк `sshd_config`. Поэтому `00-local.conf` с `PasswordAuthentication yes` побеждает `PasswordAuthentication no` и в `50-later.conf`, и в основном файле.

Роль делает две вещи:

1. Сама раскрывает `Include` и запоминает файл-источник.
2. Сверяет результат с `sshd -T`, то есть с разбором настоящего `sshd`.

Если значения расходятся, контроль не проходит. Блок `Match`, который снова включает пароль или вход root, тоже считается нарушением: для части подключений демон всё ещё содержит эту возможность. `Match Address` без `AllowUsers` / `AllowGroups` доступом не ограничен: клиенты вне блока живут по глобальным правилам.

Если файлы новее процесса `sshd`, отчёт говорит, что демон не перечитал конфигурацию. `sshd -T` показывает диск, а не то, что уже загружено в память.

## Тесты на macOS

Нужны Python 3.11 или новее, Docker Desktop и запущенный демон Docker. На macOS сокет демона обычно `~/.docker/run/docker.sock`, а не `/var/run/docker.sock`. `make test` подставляет его сам, если `DOCKER_HOST` ещё не задан. Юнит-тесты парсеров Docker не требуют и работают на системном Python:

```bash
python3 -m unittest discover -s tests -v
```

Полный прогон в локальном контейнере Ubuntu 24.04. `make test` сначала собирает образ `host-audit-ubuntu2404:local` из `molecule/Dockerfile`. Базовый слой берётся с `public.ecr.aws`, поэтому для тестов не нужен рабочий логин в Docker Hub.

```bash
make PYTHON=python3.12 test-vulnerable
make PYTHON=python3.12 test-hardened
```

`make test` собирает образ, выставляет сокет Docker Desktop и запускает оба сценария вместе с юнит-тестами. Если `python3` уже 3.11 или новее, префикс `PYTHON=` не нужен. Если в оболочке экспортирован `ANSIBLE_STRATEGY=mitogen_linear`, `make` переключает прогон на встроенную стратегию: playbook'и Molecule этот плагин не подключают.

Два сценария проверяют противоположные исходы:

- `vulnerable` — ранний drop-in включает пароль и root, поздний `no` игнорируется. Ожидается `fail` по всем контролям. В отчёте SSH-01 указан файл `00-insecure.conf`.
- `hardened` — ранний drop-in задаёт безопасные значения, а основной файл ниже `Include` намеренно содержит `yes`. Ожидается `pass`. Если смотреть только на основной файл, этот сценарий не сойдётся.

`auditd` в контейнере Docker Desktop иногда не стартует: у ядра виртуальной машины нет audit. Тогда AUD-01 получает `warn`, а не `fail`, при условии что правила и unit на месте. На обычном хосте незапущенный auditd — это `fail`.

`host_audit_time_require_synchronized` в сценариях выставлен в `false`: контейнер часто не может подтвердить `NTPSynchronized=yes`. На боевых хостах значение по умолчанию — `true`.

В сценарии `hardened` из проверки ядра исключены `kernel.dmesg_restrict`, `kernel.kptr_restrict` и `kernel.yama.ptrace_scope`: внутри Docker они часто только для чтения. В `defaults/main.yml` список исключений пуст, на сервере эти параметры проверяются.

Образ собирается локально: `molecule/Dockerfile` на базе Ubuntu 24.04. Контейнер привилегированный, команда запуска — systemd. На Apple Silicon первый запуск может идти через эмуляцию и занять несколько минут.

## Ограничения

- Роль не приводит хост к профилю. Исправления описаны в отчёте и в [docs/controls.md](docs/controls.md), применять их нужно отдельно.
- PAM для MFA не исполняется по шагам. Проверяются `AuthenticationMethods`, `UsePAM` и строка `required` или `requisite` известного модуля второго фактора.
- Алиасы sudoers раскрываются на один уровень. Правило «все команды» ищется как `ALL` или как `Cmnd_Alias`, который равен `ALL`.
- Состояние `Match` при `Include` внутри блока передаётся вглубь, но не моделирует все редкие комбинации OpenSSH. Расхождение с `sshd -T` всё равно валит контроль.
- Firewall понимает типичный ufw, firewalld, цепочку input в nftables и `iptables -S`. Сложный переход по пользовательским цепочкам может дать ложное нарушение, и это видно в тексте доказательства.
- Центральная доставка логов проверяется по конфигурации и состоянию сервиса, без пробного сообщения на приёмник.
- Списки лишних пакетов, сервисов, портов и демо-учёток — политика этого репозитория. Чужой базовый набор задаётся переменными, а не правкой задач.

## Состав

```text
defaults/main.yml          пороги и списки
tasks/                     сценарий проверки
library/                   разбор sshd и заголовков ключей
filter_plugins/            решение pass/fail по собранным фактам
meta/                      galaxy и argument specs
molecule/vulnerable/       хост, который должен провалиться
molecule/hardened/         хост, который должен пройти
tests/test_audit.py        парсеры без Docker
docs/controls.md           что означает каждый контроль
run-host-audit.yml         запуск роли на одном или многих хостах
```
